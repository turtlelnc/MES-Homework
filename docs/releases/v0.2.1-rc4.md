# v0.2.1-rc4（build 26102501）— OAuth 登录方式升级

本版本保留 v0.2.1-rc3 的桌面版无依赖一键部署器与全部功能，并重做 OAuth 模型链接：

## OAuth 变更

- **移除** OAuth provider：Claude、Qwen（国际版）、千问（国内版）、DeepSeek（Platform）。
  （API Key 方式的厂商预设不受影响。）
- **ChatGPT（Codex OAuth）**：支持两种登录方式，均由用户点击浏览器授权完成：
  - **浏览器回调 + PKCE**：打开 ChatGPT 授权页，本机 127.0.0.1:1455 接收回调后自动完成；
  - **设备码（Device Code / Codex OAuth）**：显示一次性用户码与 `https://auth.openai.com/codex/device`，
    用户输入后由服务端自动轮询完成；
  - 登录后通过 ChatGPT Codex Responses API 调用模型（无需 API Key）。
- **WorkBuddy**：OAuth 浏览器登录 + 设备码登录（国内版默认，可切换国际版）：
  点击「浏览器登录」直接打开授权页，或点「设备码登录」查看授权链接；两者底层走同一套官方 state → 授权页 → 轮询流程，服务端自动换取令牌，用户无需复制 token。
- **Gemini（Google）**：保留浏览器 OAuth + PKCE；部署方在环境变量配置 Google OAuth Client ID/Secret
  （Desktop app），未配置时界面显示「未配置」与所需变量。
- 新增令牌附加身份存储（`oauth_connections.meta_json`，迁移兼容旧库），令牌仍 AES-256-GCM 加密。
- 统一登录对话框：浏览器登录自动回到应用；设备码显示用户码/授权链接并自动轮询；支持取消与断开连接。

## 升级说明

- 版本：`v0.2.1-rc4`，构建号 `26102501`。
- 数据库启动时自动迁移（新增 `meta_json` 列），旧数据与旧连接保留；已移除 provider 的旧连接不再显示，
  但不影响其他数据。
- UI：设置 → OAuth 卡片只剩 ChatGPT / Gemini / WorkBuddy，按支持的流程显示「浏览器登录」「设备码登录」。
- 环境变量：`.env.example` 已同步；ChatGPT 无需配置 Client ID（内置 Codex 公共 PKCE 客户端），
  WorkBuddy 可用 `OAUTH_WORKBUDDY_REGION=cn|global` 选择区域，Gemini 仍需 `OAUTH_GEMINI_CLIENT_ID/SECRET`。
- 旧桌面部署器无变化，仅版本号随 rc4 更新；Release 资产包含各平台单文件部署器与运行时包。

## 已知限制

- ChatGPT Codex OAuth 与 WorkBuddy 使用的是各官方 CLI/客户端的公开授权流程；上游接口变化可能导致登录失效，
  需要时按上游新协议调整。
- ChatGPT / WorkBuddy 的模型调用走各自上游接口；真实账号联调需要在目标环境手动验证（本仓库测试使用
  mock fetch，不访问真实账号）。
- Gemini 需要在 Google Cloud 创建 OAuth 客户端并配置环境变量；中国大陆境内无法使用 ChatGPT/Gemini。
- 生产环境仍需 HTTPS 反向代理（Secure Cookie），服务器版服务安装需要管理员/root 授权。
