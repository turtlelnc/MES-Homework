# MES-Homework v0.2.3-rc2（build26111501）

## 本次变更

1. **复核界面重做**：顶部改为状态条（状态徽章 + 学生 + 一句说明 + 单一主按钮），匹配学生单独成块并说明它会做什么，原件改为紧凑的「第 N 页 · 文件名」，按钮由「开始 OCR」改为「开始识别」。面向零基础教师，删去堆在一行里的次要信息。
2. **附件名乱码修复**：还原百分号编码并修正 UTF-8/latin1 误解码，不再出现 `%E5%85%A8…pdf` 这样的文件名。
3. **教师批量导入**：新增 `POST /api/teachers/import`（CSV/XLSX，单次最多 200 人，账号名与密码留空自动生成），并写入任课关系；学校管理页提供导入面板与「教师导入模板.csv」。
4. **一校多管理员**：教师列表包含管理员并带标记，`PATCH /api/teachers/:id/admin` 可提升或取消管理员，且不允许取消最后一位管理员。
5. **一键匹配本班学生**：`POST /api/assignments/:id/auto-match` 按 OCR 姓名批量匹配该作业下未匹配的答卷（限本校、同学段同班级、姓名唯一），复核页显示已匹配与待确认数量。
6. **测试基础设施**：vitest 不再把 `.npm-packages/` 中的打包源码当作测试收集。

## 数据与升级

无新增表或字段，`school_invites`、`provider_settings`、`class_teachers` 等沿用现有结构。升级后教师列表会开始显示学校管理员（此前被过滤掉），这是预期变化。

## 验证

- `tsc -b --force`、`vite build` 通过；单元测试 61 项通过。
- 浏览器用例「两页组成一个提交」「学校成员表单」等通过；复核面板截图见 `docs/screenshots-v0.2.1/12-review-panel-redesign.png`。
- `auto-match` 接口对 fixture 服务实测返回 `{matched, unmatched, pending}`。
- 教师导入接口需要学校管理员会话，未在真实环境完成一次完整导入验证；批量匹配未在真实作业数据上验证。

模型调用仍全部为 mock；未构建或签署原生安装包。
